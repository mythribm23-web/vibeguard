The Engineering Dilemma

Why Existing Scanners Fail Vibe Coders

Developers are forced to pick between speed (vibe coding) and security (slow tools).

❌ Traditional Security Scanners (Bandit / Semgrep)

Heavyweight CLI tools take 1,200ms – 3,500ms per scan, operate after commits in CI/CD, and offer zero auto-patching. Developers disable them to stay in the zone.

❌ LLM-as-a-Judge Reviewers

Calling ChatGPT or Claude introduces 2–5 seconds latency, variable nondeterministic answers, token costs, and violates Track 3 research boundaries.

Track 3 Research Rule 1

Our Research Hypothesis & Methodology

Testing deterministic generation-time static analysis against AI coding flaws.

Formal Research Hypothesis:

"Security flaws in AI-generated code can be intercepted and remediated at generation time using deterministic Abstract Syntax Tree (AST) taint analysis and entropy heuristics, significantly reducing vulnerabilities with under 50ms latency overhead."

🔬 Local Execution: Analysis runs locally, avoiding network/API latency, guaranteeing 100% reproducible execution.

System Architecture

Three Deterministic Interception Engines

Sitting directly at the generation boundary before code is executed or shipped.

1. Secret Detection Engine

Pattern matching + Shannon entropy (>4.2) detects keys (`sk-`, `ey...`, `AKIA`) without external cloud calls.

2. AST Taint Analyzer

Parses syntax trees locally to track user request inputs into SQL execution sinks and missing route auth.

3. 1-Click Auto-Patcher

Rewrites unsafe queries into parameterized bindings (`?`, `$1`) and auto-extracts secrets into `.env.local`.
